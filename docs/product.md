# 章枢 产品需求

## 定位

章枢是职业网文作者与 AI 协作写长篇连载的工作流，由 Agent 读取的 skill、SOP 和书籍工作区模板组成。它装进作者已经在用的编程 Agent 里运行，不自带编排器，不直接调用模型。

它要做到两件事：作者的劳动集中在 AI 做不好的长线节奏和情节上，其余体力活交给 AI；作者和 AI 之间的每次交接都有固定的格式和路线，不靠作者每章临场想办法。

## 问题

### 全自主写长篇，越长越差

AI 写短篇已经强过多数人，篇幅一长就失控。旧版章枢（2026-04）实测出的病灶是“连续事故处理流”：每章都有局部危机和解法，单章看都成立，连起来读，读者疲劳。

这是结构问题。模型每次只对眼前这一章负责，它看得到上一章发生了什么，看不到读者现在累不累、欠着读者什么、什么时候该还。节奏是跨几十章的读者体验，不存在于任何单独的一章里。

GitHub 上的主流项目（见 [ADR 0002](adr/0002-build-minimal-not-on-skill-packs.md)）把力气花在一致性上：伏笔登记、设定不打架、人物不 OOC。这些是必要的，但一致性只保证不写崩，不保证好看。用配额管节奏（主线占 60%、主线连续不超过 5 章）是把审美降成指标。

### 人机协作没有工作流

不搞全自主，作者就得到处补锅。问题出在补的位置不对、补的方式不固定：

- **修错层**。一章读着不对，病根多半在章纲或单元节奏，作者却在正文里逐句改，改完下一章同样的病又来。
- **改了白改**。作者手改过的正文，AI 写下一章时不知道；作者反复改的同一种毛病，AI 永远学不会。webnovel-writer 的 #77、#100：作者手改正文后，状态库与正文脱节，没有同步办法。
- **介入点分散**。一章要经过构思、章纲、起草、审读、修改、记账，作者每一步都可能插手，每次插手的方式都不一样。

## 用户

第一位用户是一位靠写网文吃饭的同志。他会学会使用 Agent 和 GitHub，在我们打好底子后接手维护章枢本身。这决定了两件事：

- 工作流按职业作者的日更节奏设计，不按“一句灵感生成整本书”设计。
- 写作手艺必须写在作者能读、能改的 Markdown 里。

待向他确认（影响 M1 范围）：

- 平台、题材、日更字数
- 现在的写法：有没有大纲、大纲细到哪一层、每章的时间花在哪
- 用哪个 Agent 和模型，在 Windows 还是 macOS 上写

## 产品原则

### 按认知状态分层，每层归属明确

工作区按内容的认知状态分层：可能发生（构想）、已经确定（百科）、将要发生（大纲）、待定稿（草稿）、已经讲给读者（正文）。每层写明谁写、谁拍板；账本是派生的，只由 AI 从上游重算。见 [ADR 0003](adr/0003-workspace-layers-and-ownership.md)。

### 节奏和情节归作者，AI 让偏离看得见

作者在单元层排节奏，AI 在单元内起草，并逐章记账：这章实际交付了什么、兑现了什么、新欠了什么。AI 不替作者决定节奏，它的职责是让偏离在第 3 章就被看见，而不是第 30 章。见 [ADR 0004](adr/0004-author-owns-pacing.md)。

### 介入只有一种格式，改在病根所在的层

作者只写批注，由 AI 判断病根在哪一层、改上游、再重做下游。作者的修改是最值钱的数据：草稿到定稿的差异沉淀进作者手册，同样的毛病下次不再出现。见 [ADR 0005](adr/0005-annotation-routing-and-author-handbook.md)。

### 薄

引擎只是 skill、SOP、模板和少量检查脚本。宿主、模型以及去 AI 味这类通用能力都由外部提供。每加一个概念、一个步骤，先问作者会不会因此多一份活。见 [ADR 0001](adr/0001-skill-pack-in-existing-agents.md)。

## 第一阶段：用章枢写完一个真实单元

| 里程碑 | 交付 |
| --- | --- |
| M0 | 仓库、产品需求和 ADR；向作者确认待确认项 |
| M1 | 工作区模板与写章闭环：章纲 → 草稿 → 定稿 → 账本重算 |
| M2 | 节奏面板与批注路由 |
| M3 | 作者用章枢写完一个真实单元，作者手册开始积累 |

每个里程碑开始时再定具体范围，不提前展开。

完成标准：作者用章枢写完一个约 10 章的真实单元，之后还愿意继续用。过程中记录作者每章实际花的时间和花在哪一层，与他原来的写法对比；花在正文逐句修改上的比例下降，协作工作流才算成立。

## 后续阶段

只记方向，不做规划。

- **拆文**：从对标书中提取节奏样本放进参考层，供作者排单元时参照。
- **作者维护**：作者自己通过 PR 修改 skill 和 SOP，引擎随他的手艺一起长。

旧版章枢的白皮书和代码在 [LaiQiInfoTech/zhangshu](https://github.com/LaiQiInfoTech/zhangshu)。它的创作哲学延续到这里的 SOP：高压章节是稀缺资源，主角先是人再是解法，禁止挖坑不填。它的编排器、模型网关和多脑区不延续。
