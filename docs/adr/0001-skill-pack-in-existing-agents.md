# 引擎是跑在现成 Agent 里的 skill 包

状态：已接受（2026-10-20）

章枢以 skill、SOP 和模板的形式运行在作者已有的编程 Agent 里，不自带编排器，不直接调用模型。

## 背景

旧版章枢自己写了编排器、模型网关、多脑区路由和 JSON 产物校验，直接调用 DeepSeek API。推进记录里大部分条目都在修这些管道（JSON 修复、密钥脱敏、上下文消费日志），写作本身只推进到冷启动和前几章。读写文件、长上下文、子 Agent、工具调用，编程 Agent 都已经提供了。

## 决定

- skill 用通用的 `SKILL.md` 格式，不绑定某一家宿主。hook、子 Agent 等宿主特有的能力只作增强，流程不依赖它们。
- 不自带编排器，不直接调用模型 API，不把 MCP 服务或常驻进程当作运行前提。
- 本仓库只放引擎。书的工作区由模板生成在仓库外，小说的版本管理和备份不归章枢管。
- 写作手艺写在 Markdown 里；代码只做确定性的事，例如字数统计、句式扫描。
- 模型由作者自己选。流程按“模型会跳步”来设计：步骤少，关键检查交给脚本。webnovel-writer #91 的经验是，一条长 SOP 不能指望模型照做。

## 后果

作者能读懂并改动引擎的每一部分，这是他接手维护的前提。代价是我们不控制运行时，宿主之间的能力差异只能在 skill 里写降级办法。
